# Decisions

One line each: the choice, the alternative, why. The README pulls from this file.

| # | Choice | Alternative | Why |
|---|---|---|---|
| 1 | Two-pass: narrate, then extract a delta with a cheaper model | Single call returning `{narration, delta}`; tool-calling narrator | Mixing creative and analytical work degrades both on open-weight models, and a single call can't stream cleanly. Tool calling is the more agentic answer and is listed as next-day work |
| 2 | `apply_delta()` validates against the world bible and *drops* bad fields | Raise on invalid delta | A dropped state update is recoverable; a crash mid-adventure is not. Rejections are logged, never surfaced to the player |
| 3 | `add_items` requires the item id to exist in the bible, but **not** to be present in the current scene | Strict scene-presence check | Strict checking blocks legitimate NPC gifts and rewards. Bible-only keeps the containment boundary meaningful without fighting plausible fiction; out-of-scene adds are logged as warnings |
| 4 | Context truncation drops oldest verbatim turns first, then trims the summary, and never drops the scene or state blocks | Proportional trim across all sections | Scene and state are the correctness guarantee. Narrative memory is lossy by design, so it is the right thing to spend first |
| 5 | Token budget estimated as `len(text) // 4` | Real tokenizer (`tiktoken`) | The cap is a coarse safety valve, not an accounting system. Not worth a dependency or the wrong-tokenizer-for-the-model problem |
| 6 | Relationship notes and established facts are capped and de-duplicated in `apply_delta` | Unbounded lists | State is injected in full every turn, so unbounded growth is a context leak. Caps keep the "always inject everything" guarantee affordable |
| 7 | The opening scene is printed verbatim from `world.yaml` with no model call | Have the narrator generate turn 1 | Turn 1 is deterministic, instant, and free, and it anchors the world's voice before the model ever speaks |
| 8 | Extractor JSON is requested via `response_format={"type":"json_object"}` when the model supports it, probed once at startup | Assume support; or always prompt-enforce | Structured-output support is per-model on Novita. Probing once costs one cheap call; the fence-stripping fallback is needed either way |
| 9 | ~~Narrator `moonshotai/kimi-k2-instruct`, extractor `meta-llama/llama-3.3-70b-instruct`~~ **superseded by 28** | One `MODEL` setting for both | Kept for the reasoning, which still holds: the roles are separate settings because they want different things — prose quality versus JSON reliability and cost — and the extractor never has to write a sentence anyone reads. The narrator half was wrong. kimi was chosen as the best prose "of the instruct models tried", but it is a reasoning model and starved exactly as the two before it had; see 28 |
| 10 | Base URL is `https://api.novita.ai/openai` | `.../openai/v1`, as the design docs originally had it | Verified against the live endpoint. The `/v1` form was wrong and would have 404'd every reviewer on turn one — the reason Gate G0 exists |
| 11 | Narrator must be an instruct-tuned model, not a reasoning model | Raise `max_tokens` until a reasoning model finishes thinking | Verified live: `deepseek-v4-flash` spent all 500 tokens in `reasoning_content` and emitted no prose. Paying for invisible deliberation before every sentence is the wrong trade for a narrator, and it makes latency unpredictable. The client now warns explicitly when a stream is reasoning-only |
| 12 | Item `description` and `notes` are injected for every item in the scene *and* in the player's inventory | Inject item names only (the original behaviour) | Names alone left the narrator to invent what a letter said — observed live on turn one, where it fabricated a midnight meeting instead of the letter's authored text. `description` goes in ITEM DETAIL, `notes` in DM-ONLY NOTES. Carried items keep their canon so a pocketed letter reads the same later |
| 13 | A dropped delta prints a visible warning to the player | Log it and move on, as before | Found live: with a reasoning model on the extractor, two turns narrated beautifully while recording nothing, and only `/state` revealed it. Dropping the delta stays correct — a crash mid-adventure is worse — but silence turns a contained failure into an invisible one |
| 14 | The extractor is shown an ALREADY CANON block (world history, current location's secrets and description, notes for carried items) | Rely on the prompt's instruction to exclude bible facts | Observed live: a 2-turn session recorded three `established_facts`, all three already in the bible and two of them the same claim twice. The extractor was told to exclude canon but never shown it, so it could not tell canon from invention. Costs ~320 tokens on a call that already carries the id lists |
| 15 | Near-duplicate ledger entries are suppressed by significant-word overlap (0.6) and the suppression is reported as a rejection | Exact string de-duplication only | The ledger is injected in full every turn, so restatements are a compounding context leak. The threshold is a heuristic calibrated on the real case above, so it reports every suppression to `game.log` rather than silently dropping a detail |
| 16 | Validator rejections are fed back to the narrator as CORRECTIONS on the next turn | Log them only, and accept prose/state divergence as a known limitation | Observed live: an illegal move to the lamp room was correctly refused, but the narration described the climb and the arrival anyway, leaving the story two rooms from the state. Rejections were already being computed and thrown away — feeding them back makes `apply_delta` a control signal rather than only a log. Only player-visible rejections qualify; bookkeeping ones stay silent |
| 17 | Hard rule 2a: travel is one listed exit per turn, and the narrator is told it has *not been shown* what other locations contain | Rely on rule 1's "do not invent undefined places" | Observed live: asked to go straight to the lamp room, the narrator described arriving and invented the room — a dead lamp, in a world whose premise is that the light has burned every night for eleven years. Rule 1 did not bite because the lamp room is not *undefined*, merely not present. Naming the real reason ("you have not been told, so you would be inventing") gives the model something honest to act on, and "stop at the foot of the stair" gives it a legitimate move. The extractor is told to match: report the adjacent step, not the intended destination |
| 18 | Hard rule 2b: never assert the *condition* of a place the player is not in, and treat WORLD HISTORY as outranking the narrator's own earlier prose | Let the verbatim buffer keep the narration self-consistent | Observed live: having wrongly called the great lamp "dark" once, the narrator repeated it the next turn — the mistake was now in its own transcript, so staying consistent meant staying wrong, in a world whose premise is that the light has never gone out. Rule 2a stopped it travelling into unseen rooms but not asserting things about them. Telling it plainly to abandon its own contradicted line is cheaper than a canon validator, which stays next-day work |
| 19 | Prompts are markdown files in `llm/prompts/`, loaded at import, rendered with `string.Template` (`${name}`) | A single `prompts.py` of Python string literals, as originally specified in CLAUDE.md | Prompts are content, not code: editing one should diff as prose and need no escaping. The template engine is the load-bearing half — `extractor_system.md` is mostly a JSON schema and a worked JSON example, and `str.format` would read all 6 of its braces as fields. `Template` only touches `$`, so the JSON passes through untouched. Loading at import keeps a missing file or unfilled placeholder a startup failure rather than a mid-game one |
| 20 | A move to a non-adjacent but reachable location walks the player one hop along the shortest path, rather than being refused | Refuse the whole move (original); or instruct the extractor to report the adjacent step itself | The instruction-to-the-extractor version was tried and observed failing live: it proposed `lamp_room` anyway, the move was refused, and the player sat in the entrance for three turns while the narration climbed a tower — which is also why the CORRECTIONS block could not win. Path-finding is a topology question with an exact answer, so it belongs in code, not in a prompt. Refusing outright was worse than both: the player's intent was legitimate, they simply cannot teleport |
| 21 | Only 429 and 5xx are retried; 4xx breaks out immediately | Retry every `APIError` | The json-mode probe hits a 400 ("response format json_object is not supported") on models that lack it. That request is just as wrong the second time, so the retry bought nothing and cost a 2s backoff on every startup |
| 22 | The extractor is told that "at the foot of", "at the threshold of" and "looking toward" are not arrival | Leave "move_to only if the player arrived" to be interpreted | Observed live: the narrator correctly refused to move the player ("You stand at the foot of the Spiral Stair, the rusty key and sealed letter still lying on the table") and the extractor recorded the move anyway, putting state a room ahead of the story. Threshold language is exactly what hard rule 2a asks the narrator to produce, so the two prompts have to agree on what it means |
| 23 | The narrator's scene block lists exits by display name only; internal ids go to the extractor alone | Show `Name [id]` to both, as originally | Observed live: the narrator ended its replies with `Exits: The Spiral Stair [stair_ascent], ...`, copying the scene block's scaffolding — ids included — straight to the player, and garbling it on the second turn (`The Spiral Stair [lamp_room]`), which shows it was mimicking the format rather than reading it. The narrator never proposes a move, so it never needed an id. Hard rule 3a says the briefing is not a format to copy |
| 24 | Deterministic tests run against `tests/fixtures/world.yaml`, not the shipped world | Test against `dungeon_master/world/world.yaml` directly, as originally | The world file is content and gets rewritten as the fiction improves — the first rewrite broke 27 tests that had done nothing wrong except quote its ids. Rules are now tested against a dull fixture world with a topology chosen to exercise them (a two-hop chain, a branch, an unreachable room). The shipped world is checked only for what must be true of any world: it loads, it validates, it stays within the CLAUDE.md budget, every location has secrets and every NPC has wants/knows/hides, and no room is unreachable from the start |
| 25 | World rewritten from The Keeper's Reach to The Long Ebb | Keep the seeded world | The premise was chosen deliberately this time — storm coast, quiet dread, someone who does not know what they are — rather than inherited from the seed in PLAN.md. Same three pillars, everything else new. Cost: every README transcript was captured in the old world and had to be marked stale rather than shipped as fiction about a game that no longer exists |
| 26 | Hard rule 2a is split into two named cases: a destination **listed under Exits** is a yes and the narrator describes arriving; anything else stops at the threshold | One movement rule covering both | Observed live: `I walk out onto the flats` was met with a threshold even though the shore path is a listed exit, and the extractor — correctly applying decision 22 — reported no move. The player sat in the opening room for an entire session and `/state` stayed empty. Rule 2a had been written for the illegal-teleport case (decision 17) and was being applied to every move, so the two halves had to be named separately. The extractor gets the mirror: threshold language cancels only the place it is attached to, so a player stopped below the lamp room is still reported as being *in the stair* |
| 27 | `dm_system.md` opens with an EVERY TURN section describing what a good turn does, and closes with a worked example turn | Hard rules alone | Decisions 16–18, 20, 22 and 23 each added a prohibition after a live failure. Each was individually right, and the sum was seven NEVERs against one positive instruction — a prompt that described only the failure modes. The observed result was defensive prose: three consecutive turns that re-listed the same furniture, let nothing happen, and stated a DM-only secret outright. A model steers toward what is described, so the job now gets described too — something changes, the world acts on its own wants, detail is spent rather than re-listed, secrets arrive as evidence, and a permitted action is a yes |
| 28 | Narrator moved to `meta-llama/llama-3.3-70b-instruct`, the same model as the extractor — **this supersedes decision 9** | Keep `kimi-k2-instruct` for its prose; or raise `max_tokens` until a reasoning model finishes thinking | Decision 9 picked kimi because it wrote the best prose and llama was "reliable but flat". The prose judgement was right; the classification was not. `game.log` records `NARRATOR_MODEL=moonshotai/kimi-k2-instruct` spending its entire 1200-token budget on reasoning and emitting no prose on three separate turns, and a live probe caught its sibling `kimi-k2-0905` doing the same and then printing its own chain of thought to the player as if it were narration — through `content`, where nothing can filter it. Measured one turn each: `glm-4.7-flash` spent 1051 of 1200 tokens reasoning and took 77s; `sao10k/l31-70b-euryale-v2.2` wrote the best prose of all five and invented a man, a horse, a gate and a wall, then put the light out. An `-instruct` suffix predicts nothing. Flatness is the right thing to trade away here, and decisions 26–27 buy most of it back in the prompt rather than the model — a DM's job is consistency, and fluency that invents is worse than plainness that does not |
| 29 | The loop resumes its own autosave on startup, and a new game seeds the transcript with the opening scene | Start fresh every launch, as before | Two halves of the same oversight. The loop autosaved every turn and never read the file back, so every launch silently restarted the adventure — visible in `game.log` as the same opening turns replayed across three sessions. And `opening_scene` was printed to the player but never appended to the transcript, so on turn 1 the narrator answered "I pick up the letter" with no record that a letter had been mentioned. An unreadable save falls back to a new game rather than dying at startup |
| 30 | The transport owns the only retry layer (`max_retries=0` on the SDK), 5 attempts, exponential backoff capped at 8s | Keep the SDK's retries and raise ours on top; or uncapped doubling | Observed live: Novita answered `429 server overload` on roughly a quarter of the calls in one session and every one cost a whole turn, because the bursts outlast the 2s the old budget could wait. The deeper problem was legibility — the SDK retries twice inside each of ours, so `attempts=2` was really six requests, and a budget nobody can read off the code is one nobody can tune. Collapsing to one layer trades away the SDK's `Retry-After` handling for a number that means what it says. The cap matters as much as the count: 2, 4, 8, 8 is 22s of worst-case waiting, which a spinner can carry, where uncapped doubling would put a 60s stall in front of a blocking turn. A 4xx still breaks out on the first try (decision 21), so startup did not get five times slower |
